# Стиль кода для разработчиков

## Общие правила

- Следуйте стилю существующего модуля, если он не противоречит этому документу.
- Имена должны описывать назначение сущности; избегайте необъяснимых сокращений.
- Комментарии должны объяснять причину или ограничение решения, а не повторять
  очевидный код.
- Комментарии и документация пишутся на русском языке, если локальные правила
  репозитория не требуют иного.
- Не изменяйте вендорный или сгенерированный код без отдельной необходимости.
- Для форматирования и статического анализа используйте инструменты,
  закреплённые в конкретном репозитории.

## C и C++

- Классы и шаблонные параметры именуются в `PascalCase`.
- Методы, функции и переменные именуются в `snake_case`.
- Макросы и константы именуются в `UPPER_SNAKE_CASE`.
- Публичные классы, функции и методы документируются Doxygen-комментариями с
  `@brief`, а при необходимости — с `@param`, `@return`, `@note` и `@details`.
- В публичных заголовках используйте классические include guards
  `#ifndef` / `#define` / `#endif`; имя макроса — в `UPPER_SNAKE_CASE`.
- Для embedded-кода не вводите динамическую аллокацию и полиморфизм на базе
  `virtual`, если существующая архитектура использует статические буферы и
  статическую диспетчеризацию.
- Не создавайте новый namespace или новый архитектурный паттерн без обсуждения
  с командой.

## Python

- Каждый модуль начинается с docstring, описывающего его назначение.
- Импорты разделяйте на системные, внешние и пользовательские.
- Классы именуются в `PascalCase`; функции, методы и переменные — в
  `snake_case`.
- Используйте type hints для параметров, возвращаемых значений и атрибутов
  экземпляров.
- Публичные классы и методы документируйте в стиле Google docstrings:
  `Args:`, `Returns:`, `Raises:`.
- Для приватных атрибутов используйте один префикс `_`.
- При работе с текстовыми файлами явно указывайте `encoding="utf-8"`.

## Локальные дополнения

Репозиторий может уточнять или дополнять эти правила в собственной
документации. Локальные правила не должны ослаблять требования безопасности и
качества, принятые для организации.
