# Локальная рабочая область

Этот документ описывает рекомендуемую организацию локальных каталогов для работы с репозиториями компании.

## Принцип

Все рабочие репозитории располагаются в едином корневом каталоге. Это упрощает навигацию, настройку IDE, ссылки между проектами и последующую автоматизацию подготовки окружения.

## Рекомендуемая структура

```text
<workspace-root>/
├── .github/                                      # Общие настройки GitHub организации
├── boards/
│   └── Miluino_MA1/
│       └── hardware/                              # Miluino_MA1_hardware
├── dev-guidelines/                                # Общие правила и инструкции
├── kits/
│   └── Miluino_MA1_StudyKit/
│       ├── firmware/                              # Miluino_MA1_StudyKit_firmware
│       └── hardware/                              # Miluino_MA1_StudyKit_hardware
└── platforms/
    └── mdr1986/                                   # mdr1986
```

`<workspace-root>` разработчик создаёт самостоятельно. Сначала в него клонируется `dev-guidelines`, затем из этого репозитория запускается подходящий скрипт: `scripts/bootstrap-workspace-windows.ps1` для Windows или `scripts/bootstrap-workspace-linux.sh` для Linux. Скрипты по умолчанию определяют `<workspace-root>` как родительский каталог `dev-guidelines`.

Репозитории располагаются в каталогах, соответствующих их назначению: платы — в `boards`, комплекты — в `kits`, платформы и библиотеки — в `platforms`. Скрипт создаёт промежуточные каталоги автоматически.

## Правила

- Один локальный каталог соответствует одному Git-репозиторию.
- Путь и имя каталога репозитория должны соответствовать `config/repositories.json`.
- Личные эксперименты, временные файлы сборки и IDE-кэши не хранятся в `dev-guidelines`.
- Список репозиториев и их назначение поддерживается в [repositories.md](repositories.md).
- Разработчики клонируют только уже утверждённые репозитории; новые репозитории в организации создаёт администратор.

## Управление инструкциями

Содержимое `dev-guidelines` ведёт только администратор. Разработчики могут использовать инструкции и скрипты репозитория, но не добавляют и не изменяют его материалы без явного поручения администратора.

## Автоматизация

`scripts/bootstrap-workspace.ps1` создаёт недостающие каталоги и клонирует репозитории, назначенные указанной команде. Состав наборов хранится в `config/repositories.json`.
